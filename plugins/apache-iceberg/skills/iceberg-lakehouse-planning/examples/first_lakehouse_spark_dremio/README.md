# First lakehouse: PostgreSQL -> Spark -> Iceberg (Nessie) -> Dremio -> BI

One local lakehouse shared by four test modules: PostgreSQL source, SeaweedFS (S3 API), Spark 3.5.5 +
Iceberg 1.8.1, Nessie 0.76.6 (in-memory), Dremio OSS 26.0.5. The BI layer (Superset) is not deployed:
`bi_dashboard` sends the same chart queries over Arrow Flight and renders a PNG.

| File | Shows |
|---|---|
| `docker-compose.yml`, `Dockerfile` | Pinned stack on one user-defined network; PostgreSQL JDBC jar baked into the Spark image; Dremio memory capped at 2 GB heap + 2 GB direct |
| `config/postgres-init.sql` | `fashion_sales` source table: 5 seed rows + 2,995 deterministic rows over 92 days |
| `config/s3.json` | SeaweedFS identity (local dev credentials) |
| `common/lakehouse.py` | Spark `SparkCatalog` + `NessieCatalog` + `S3FileIO` config, S3 listing, JDBC DML through Spark's JVM |
| `common/dremio.py` | Dremio REST client (bootstrap admin, add source, SQL jobs) and `flight_query()` over Arrow Flight |
| `environment_health_check/environment.py` | One protocol-level probe per role (JDBC count, `head_bucket`, Nessie `/config`, Dremio `/apiv2/server_status`); reports, never raises |
| `spark_ingestion/ingest.py` | `full_reload()` with `writeTo().createOrReplace()`; `incremental_append()` with a high-water mark pushed into PostgreSQL |
| `spark_ingestion/test_spark_ingestion.py` | Source vs Iceberg fingerprint, JDBC type mapping, file layout, Nessie entries/contents/history, `gc.enabled=false` |
| `dremio_queries/dremio_lab.py` | Nessie source config for Dremio, `table_snapshot`, `AT SNAPSHOT '<id>'`, files scanned from the job profile |
| `dremio_queries/test_dremio_queries.py` | Same answer in Spark and Dremio, no copy, shared snapshot history, pruning 1 of 6 vs 6 of 6 files |
| `bi_dashboard/semantic.py` | Curated views (region, segment, campaign), charts as `(dimension, metric)` data, Flight execution, PNG render |
| `bi_dashboard/test_bi_dashboard.py` | Chart results equal PostgreSQL aggregates (Decimal equality); views stored in Nessie as `ICEBERG_VIEW` |

## Prerequisites

- Docker with Compose v2, about 6 GB free RAM for the VM (Dremio alone uses ~1.6 GiB).
- Images: `tabulario/spark-iceberg` (built and tested at Spark 3.5.5 / Iceberg 1.8.1 / pyarrow 17.0.0;
  pin the tag when reproducing), `projectnessie/nessie:0.76.6`, `dremio/dremio-oss:26.0.5`,
  `postgres:16-alpine`, `chrislusf/seaweedfs`.
- No host ports are published; tests run inside the Spark container.

## Run

```bash
docker compose -p iceberg-first-lakehouse up -d --build
docker compose -p iceberg-first-lakehouse exec -w /home/iceberg/labs spark-iceberg python -m pytest -v
docker compose -p iceberg-first-lakehouse down -v
```

On Git Bash for Windows prefix `docker compose exec` with `MSYS_NO_PATHCONV=1`. The full run (17 tests)
takes about 2.5 minutes on a fresh stack; the first test waits for Dremio to boot.
`bi_dashboard/output/sales_analytics.png` is generated by the last test.

## Fixes

- Removed source references from comments and docstrings; Spark app name is `lakehouse-tests`;
  compose project name is `iceberg-first-lakehouse`; lab folders renamed to topic names
  (`environment_health_check`, `spark_ingestion`, `dremio_queries`, `bi_dashboard`) and imports/`pytest.ini` updated.
- The source-referencing `Role` field renamed to `Role.classic_tool` (`environment_health_check/environment.py`).
- Credentials moved to environment variables with marked local dev defaults: S3 keys
  (`${AWS_ACCESS_KEY_ID:-admin}` / `${AWS_SECRET_ACCESS_KEY:-password}`), PostgreSQL
  (`${POSTGRES_USER:-myuser}` / `${POSTGRES_PASSWORD:-mypassword}`, now also passed to the Spark container),
  Dremio admin (`DREMIO_USER` / `DREMIO_PASSWORD`, default `password1`), and the Dremio Nessie source's
  `awsAccessKey` / `awsAccessSecret` (read from the S3 env vars instead of literals).
- PostgreSQL healthcheck uses `$$POSTGRES_USER` so it follows an overridden user.
- `config/s3.json` still holds the local-only `admin` / `password` identity: change it together with the
  `AWS_*` variables if you override them. Never reuse these values outside a laptop stack.
- No Iceberg/Nessie/Dremio API changes were needed.
