# Pipeline and Job Naming

## When to Use This Skill
- Creating or reviewing a DAG, job, pipeline manifest or trigger
- Naming things that appear in alerts, dashboards and run history

## Core Concepts

### Platform manifests (`metadata.name`)
Kubernetes-style DNS-1123 labels: lowercase, `[a-z0-9-]`, ≤ 63 chars, start/end alphanumeric; workspace and tenant come from context.
| Kind | Pattern | Example |
|---|---|---|
| Pipeline | `{source-or-layer}-to-{target-layer}-{entity}` or `{domain}-{entity}-{purpose}` | `landing-to-silver-orders`, `sales-orders-daily-rollup` |
| LinkedService | `{system}-{instance-or-domain}` | `erp-postgres`, `landing-adls` |
| IntegrationRuntime | `{tier}-{purpose}` or `{site}-{purpose}` | `default-pool`, `onprem-dc1` |
| Trigger | `{cadence-or-event}-{subject}` | `hourly-landing`, `on-new-file-orders` |
| Dataset | `{layer}-{domain}-{entity}` | `silver-sales-orders` |
| Policy | `{scope}-{purpose}` | `silver-access`, `pii-masking` |

### Airflow (generated by the compiler, but same rules apply to hand-written DAGs during migration)
- `dag_id` = `{tenant}__{workspace}__{pipeline}` (double underscore separates hierarchy; single underscore inside words); ≤ 250 chars; `[a-zA-Z0-9_.-]`.
- `task_id` = `{verb}_{object}` (`extract_orders`, `validate_orders`, `load_silver_orders`); task groups by stage (`extract`, `transform`, `quality`, `load`, `publish`).
- Tags: `tenant:{t}`, `workspace:{w}`, `layer:{l}`, `domain:{d}`, `owner:{team}`, `platform-generated`.
- Pools: `{tenant}-{tier}`; connections: `{tenant}__{linked-service}`; variables namespaced `{tenant}/{workspace}/{key}`.

### Spark / Flink
- SparkApplication name: `{tenant}-{pipeline}-{run-short-id}`; `spark.app.name` identical; lineage job name = pipeline name without the run id.
- Flink job: `{tenant}.{domain}.{job-purpose}` (matches streaming naming).

### dbt
- Project per workspace: `{tenant}_{workspace}`; models per data-asset-naming; jobs `{workspace}-{purpose}-{cadence}` (`finance-marts-hourly`).

### Connectors / syncs
`{tenant}.{source|sink}.{system}.{entity}` (Connect) or `{system}-{entity}-to-{layer}` (Airbyte UI names).

### Runs and correlation
`run_id` = ULID/UUID assigned by the control plane; every log/metric/lineage event carries `tenant_id`, `pipeline`, `run_id`. Alerts are named `{pipeline}.{condition}` (`landing-to-silver-orders.freshness-breach`).

## Patterns
- Names in alerts must match names in the catalog: the compiler writes both from one manifest.
- Cadence belongs to the Trigger, not the Pipeline (`orders-daily` is wrong if the pipeline can run hourly too).
- Prefer the business purpose over the tool (`sales-orders-rollup` not `spark_job_7`).

## Anti-patterns
- `dag_v2_final`, `test_dag_copy`, `john_orders`
- Task ids that are nouns (`orders`) or verbs without objects (`process`)
- Environment or date in `dag_id`
- Tool names as the primary name (`airflow_spark_load`)
