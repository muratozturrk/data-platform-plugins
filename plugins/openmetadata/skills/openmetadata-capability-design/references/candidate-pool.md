# Candidate Pool C01-C19

Nineteen capability candidates generated from the gap analysis of OpenMetadata 1.13.3
(`1.13.3-release`, `255f6694913b`) and checked for novelty. IDs are stable; keep them when you
cite. Each candidate closes named gaps (rubric IDs `Dx.y`, or platform-specific "Class 4" gaps, written
`P4.n` here (`Sınıf4.n` in the research) - e.g. P4.1 missing Iceberg connector, P4.3 no catalog↔Ranger policy link, P4.5 change events
cannot be published to Kafka). Gap definitions live in `openmetadata-gap-closing`; KVKK
obligations in `openmetadata-kvkk-compliance`.

Short paths: `spec/` = `openmetadata-spec/src/main/resources/json/schema/`, `svc/` =
`openmetadata-service/src/main/java/org/openmetadata/service/`, `ing/` = `ingestion/src/metadata/`.
Extension-point paths below were verified against the 1.13.3 tree by the research (`K`); novelty
evidence is mostly docs (`D`) and issues/PRs (`İ`). Verdicts: **new**, **partial** (pieces exist,
differentiator survives), **planned**, **exists** (eliminated). Not legal advice.

## Per-Candidate Notes

Each block: **extension point** (where it plugs into 1.13.3), **LLM sizing** (research
assumption, not a benchmark), **KVKK**, **key risk**.

**C01 Ranger derivation + drift.** Extension: Ranger is defined but empty - `spec/entity/services/securityService.json` (enum `"Ranger"`), `rangerConnection.json` (hostPort + basicAuth), `spec/metadataIngestion/securityServiceMetadataPipeline.json` (one-field stub, unchanged on `main`), `ing/ingestion/source/security/security_service.py:46` topology with no connector; trigger via `EntityLifecycleEventHandler`; drift alerts via event subscriptions. Policy-agent files (`policyAgentPipeline.json`, `supportsColumnAccess`) are **not** in 1.13.3 (2.0-targeted PRs). LLM: none. KVKK: eases data-security obligations (Law Art. 12/1, Board Decision 2018/10 "define scope of access"); syncs metadata only. Risk: sync lag opens a window → deny-by-default for new classifications + lag SLO; misclassification now has access impact → approval workflow; never bidirectional sync. Prior attempt RANGER-4978 / apache/ranger PR #544 closed (JDK mismatch, table-level only) (`İ`).

**C02 KVKK lifecycle engine.** Extension: retention model already exists - `spec/entity/data/table.json:1210-1213` (ISO 8601 `retentionPeriod`, inherited from schema/database in the repository layer); missing is any action when it expires. Copy the scheduled native-app pattern (`svc/apps/bundles/dataRetention/DataRetention.java:39,78`, Quartz; note it cleans OM's *own* data), new workflow nodes via `NodeFactory.java:44`, append-only audit log. Prerequisite: an Iceberg connector (P4.1). LLM: none. KVKK: ex officio destruction, destruction records (3 years), periodic destruction (≤6 months), data-subject requests (30 days) - store request number and row count in the record, **never the identifier itself**. Risk: rules buried in DAGs; catalog is not a deletion engine.

**C03 Transfer-regime ontology.** Extension: RDF stack - `rdf/ontology/openmetadata.ttl` (SKOS/DCAT/PROV), `svc/rdf/reasoning/InferenceEngine.java` CUSTOM rules, SPARQL resource, glossary `conceptMappings`; `RDF_ENABLED=false` by default, needs Fuseki/QLever. Transfer record = glossary term + custom properties (no new entity types). LLM: none. KVKK: Art. 9 tiers (adequacy → appropriate safeguards → incidental exceptions) and processor relationships; value is *proving* compliance. Risk: RDF operational load; modelling limits lower ease.

**C04 Special-category inference.** Extension: `personalDataTags.json` has a single undivided `SpecialCategory` tag; declarative recognizers (`spec/type/recognizer.json` family) and per-tag Presidio recognizers let you add sub-categories without code; ABAC via SpEL rules; `/permissions/debug/evaluate` as evidence. LLM: none. KVKK: Art. 6 special categories + Board 2018/10 extra safeguards. Note: conflict resolution is fixed deny-precedence (`PolicyEvaluator`), so category policies can only tighten. Risk: catalog masker is bound to `PII.Sensitive` only (`svc/security/mask/PIIMasker.java:45-46`) - per-category masking must happen in Ranger (C01).

**C05 Reference data + crosswalks** *(generalised: any domain's code lists - region codes, classification codes, type codes - that several source systems encode differently)*. Extension: glossary `conceptMappings` with EXACT/CLOSE/BROAD/NARROW/RELATED match quality; `enumConfig.json`; bulk glossary operations; embedding SPI (`EmbeddingClient.java:14`, `DjlEmbeddingClient`). LLM: embeddings in-process (DJL); switch to a multilingual model (e.g. paraphrase-multilingual-MiniLM, BGE-M3, multilingual-e5-large) by config only (`DJL_EMBEDDING_MODEL`); optional 14B-32B instruct model on vLLM, 8k context, only to write a mapping rationale. Short labels are easy, domain abbreviations may fail; fallback = manual mapping, value unchanged. KVKK: indirect (consistent data-category code list for the inventory); only code labels go to the model. Risk: no code-list entity - thousands of glossary terms; limit scope.

**C06 Governance document lifecycle.** Extension: `spec/entity/docStore/document.json:35,39,75` - `entityType` + free-form `data`, so new document kinds need no schema change; `aiGovernancePolicy.json` already has effective/expiry dates to copy; entity version history; PROV ontology. `policy.json` has only an `enabled` flag. LLM: embeddings only (drift between notice text and declared purpose); no generation, so no hallucination risk; fallback = turn drift detection off. KVKK: privacy notice obligations, burden of proof on controller (which notice version applied when). Risk: doc store extension vs core schema change decides license/upstreamability.

**C07 Ontology-backed NLQ.** Extension: cleanest hook in the repo - implement `NLQService` and set `NATURAL_LANGUAGE_SEARCH_PROVIDER_CLASS` (`NLQServiceFactory` loads it by reflection; required constructor takes `ElasticSearchConfiguration`); `SqlToSparql*` under `svc/rdf/sql2sparql/`; hybrid BM25+kNN (`OpenSearchVectorService`, OpenSearch only). LLM: Qwen2.5-32B / Qwen3-32B class, AWQ/GPTQ 4-bit on 2×A100-80GB or 4×L40S, 32k context (schema + glossary context reaches 10-20k tokens); Turkish questions over English column names need cross-lingual mapping; 7-8B degrades. Fallback: disable NLQ, hybrid search keeps working. KVKK: no rows or sample values to the model; generated query runs under the user's own identity (no privilege escalation); log query text. Risk: wrong answers erode trust - always show the generated query and source assets. Vendor spike #32048 on graph querying is still open (`İ`).

**C08 LLM classification → VERBİS inventory.** Extension: `ing/pii/processor_factory.py:14` (add an LLM branch), `base_processor.py:40`, scanners (`ner_scanner.py`, `column_name_scanner.py`), recognizer feedback (`spec/type/recognizerFeedback.json`) and the approval nodes `createRecognizerFeedbackApprovalTask` / `applyRecognizerFeedbackTask` / `rejectRecognizerFeedbackTask` (exactly propose → approve → apply). LLM: Qwen2.5-14B class, 32B for hard cases; AWQ 4-bit on one A100-80GB; 16k context (one table's schema + docs). Turkish column abbreviations (e.g. `TCKN`) must be understood. Fallback: low-confidence → "uncertain" to a human; automation rate drops, no wrong inventory. KVKK: **new risk** - send metadata only, never sample data; enforce in code. Risk: false negatives worse than false positives - keep NER, add LLM on top; no auto-apply.

**C09 Deadline primitive.** Extension: event subscriptions with SpEL + retries (strong base), Flowable workflows (supports timer boundary events); `thread.json` and `userApprovalTask.json` have no due date/timeout in 1.13.3; new escalation node via `NodeFactory.java:44` + `nodeSubType.json`; periodic batch trigger schema. `main` adds `dueDate` and `expiryTimer` (2.0, `İ`) - single node only, no escalation node, no "no deadline defined" report. LLM: none. KVKK: >20 obligations are time-bound (30 days, 72 hours, 6 months, 7 days ...); C02/C03/C10/C14 consume it. Store request number, not data-subject identity. Risk: Flowable version coupling.

**C10 Breach scope agent.** Extension: lineage API (depth + filter, CSV export, downstream owner notification), column lineage parser, test-case incident model (New/Ack/Assigned/Resolved + severity classifier) as template, append-only audit log, AI record layer for agent runs and prompt versions. LLM: Qwen2.5-14B class, 16k context; template filling from structured facts; legal review always precedes submission. Fallback: drop drafting; scope inference + category counts + countdown keep working. KVKK: 72-hour notification, category-based notification; report holds **counts and categories, not person lists**. Risk: audit log has no cryptographic integrity; Ranger audit retention must exceed the window.

**C11 Kafka governance backbone.** Extension: copy a destination under `svc/apps/bundles/changeEvent/` (email/slack/msteams/... pattern); `subscriptionType` is a closed enum without Kafka → schema change needed; consumer offset/replay already Kafka-like. LLM: none. KVKK: indirect - a lost masking decision has direct consequences; payload carries entity ID + tag change, no sample values. Risk: no CloudEvents standard. Cleanest Apache-2.0 upstream candidate.

**C12 Governance-as-code.** Extension: Git sink schema exists without implementation - `spec/governance/workflows/elements/nodes/automatedTask/sinkConfig/gitSinkConfig.json`; `SinkProviderRegistry.register` (`:52`) is only called from tests, the only provider is `WebhookSinkProvider`; CSV import/export (no CSV path for dashboards, topics, ML models, containers, pipelines); `ing/cli/restore.py` is not wired into the CLI. LLM: none. KVKK: Git history = dated, justified record of changes to legal-basis lists, retention, categories; verify exports carry no sample values. Risk: bidirectional conflicts → Git is source of truth, catalog read back only for drift.

**C13 Anonymisation evidence layer** *(capability described generically; no algorithm development)*. Extension: data-quality validators by dynamic import (`ing/utils/importer.py:247,266-270`, module path `metadata.data_quality.validations.{column|table}.{sqlalchemy|pandas}.<test>`); 25 shipped test definitions incl. custom SQL and table diff; cron scheduling on ingestion pipelines. LLM: none (statistics on Spark/Trino). KVKK: anonymisation is one of three lawful destruction methods; public sharing requires it; measurement touches raw data → store **statistics only** (k, group counts), never sample records. Risk: who picks the quasi-identifier set (derive from C04/C08 classification + human approval); petabyte cost → sample and record the confidence interval.

**C14 Public-release lifecycle.** Extension: custom property types enum/hyperlink/date; `dataProduct.json` visibility + SLA pattern; ISO 8601 duration type; NER scanner as first pass; storage connectors (S3/MinIO containers); scheduled-app pattern. LLM: Qwen2.5-14B class, 4-bit on one A100-80GB, 32k context (a document page); Turkish expectation very high (names, titles, partial masking such as initials). Fallback: model only flags pages for a human; **never auto-takedown**. KVKK: **highest new risk** - real document text reaches the model: on-prem GPU, no persistent prompt/response logs, no fine-tuning on it, store only "suspect/clean" + page number. Risk: GPU queue for thousands of documents; false negatives → keep sampled human review.

**C15 Contract circuit breaker.** Extension: `spec/entity/data/dataContract.json` (`contractSLA`, `refreshFrequency` interval+unit) defined but not evaluated; `spec/entity/datacontract/slaValidation.json` (`refreshFrequencyMet`, `latencyMet`, ...) has no evaluator anywhere (`K`); contract validation app; JsonLogic semantics rules. LLM: none (seasonal thresholds with prophet/statsmodels-class libs). KVKK: indirect - detects a periodic destruction job that silently stopped. Risk: false positives stop pipelines → observe-only mode first. Freshness requests #27173, #24538 open without milestone (`İ`).

**C16 Multilingual content.** Extension: SKOS language-tagged labels via the RDF layer; glossary synonyms/`conceptMappings`; per-language search mappings already exist (`en/jp/ru/zh`); `IndexMappingLoader.java:23-25` looks for an `elasticsearch/collate/indexMapping.json` overlay absent from the repo (empty overlay hook). UI is translated into 19 languages incl. Turkish; *content* is single-language. LLM: Qwen2.5-14B or Llama-3.3-70B class (70B 4-bit on 2×A100-80GB), 8k context; Turkish is the core of the task, 7-8B insufficient. Fallback: language-tagged model works without LLM, translation entered manually; never publish machine translation unapproved. KVKK: indirect (Turkish reporting of English enum values); check descriptions contain no personal names. Risk: touches every entity schema → start with glossary + classification.

**C17 (eliminated).** Time-bound, column-scoped, justified access requests shipped after 1.13.3 (`dataAccessRequestPayload.json` on `main` requires `reason`; policy-agent PRs #27396, #28477, #29392, #30099) and in Collate 2.0; UI logic moved from OSS to Collate (#28922 / PR #28984) (`İ`, `D`). A Ranger `validitySchedule` back-end remains open but belongs to C01.

**C18 Mandatory metadata.** Extension: `spec/type/customProperty.json:69-70` - `required` lists only definition fields, no "value required" flag, `additionalProperties:false` → schema change is the real cost; SHACL shapes (`rdf/shapes/openmetadata-shapes.ttl`, runtime-generated shapes in `RdfRepository`); `checkEntityAttributesTask` / `dataCompletenessTask` nodes. LLM: none. KVKK: unlocks many obligations whose weakest link is "field can be left empty". Ranked first in the gap guide (see `openmetadata-gap-closing`). Risk: retroactive enforcement makes thousands of assets non-compliant at once → effective date + staged scope (C06 pattern). 2.0 Custom Intake Forms cover entry time only (`D`).

**C19 AI model cards.** Extension: `spec/entity/data/mlmodel.json` (no evaluation metrics, no registry stage); `aiApplication.json` fixed-section template; `spec/type/aiCompliance.json` (EU AI Act checklists, bound to AI entities only); lineage API; PROV ontology; MLflow/SageMaker connectors. LLM: Qwen2.5-14B class, 16k context; medium Turkish need. Fallback: lineage + risk checklist without drafting. KVKK: traceability for objections to solely automated decisions (Art. 11/1(g)); EU AI Act not binding in Türkiye - mark as preparation. Risk: no Spark lineage producer in repo; OM issue #22134 open, AI Governance Studio UI removed from OSS (PR #29734) (`İ`).
